= Bonding and VLAN

In this example:

- VLAN 100 is used for container network.

- Bond0 is already configured

- bond0.100 is the container network.

- No DHCP (ipam) each Virtual Machine will allocate its own ip.

- VLAN 303 is optimized for VM networking (cnv-bridge)

-No flow control/QoS, or any other advance network features are handled by Openshift. (Linux Bridge vs OVS Bridge - br303 in example)

.nncp.yaml
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: bond0-vlan303-bridge
spec:
  nodeSelector:
    kubernetes.io/os: linux # Adjust this selector if you want to target specific worker nodes
  desiredState:
    interfaces:
      - name: bond0.303
        type: vlan
        state: up
        vlan:
          base-iface: bond0
          id: 303
      - name: br303
        type: linux-bridge
        state: up
        bridge:
          options:
            stp:
              enabled: false
          port:
            - name: bond0.303
----

.nad.yaml
[source,yaml]
----
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: vmnet
  namespace: your-namespace
spec:
  config: '{
    "cniVersion": "0.3.1",
    "name": "vmnet",
    "type": "cnv-bridge",
    "bridge": "br303",
    "ipam": {},
    "macspoofchk": true
  }'

----
