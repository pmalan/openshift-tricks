= Piraeus 

Allows you to use shared scsi luns, across 2+ node clusters. Luns can be direct attached, fibre channel or iscsi.

WARNING: Only LVM thick volumes supported, LVM thin is not supported.

WARNING: Once an LVM Thick snapshot is actively created, its mapping allocation table is still locked into the kernel memory of the source node. If you try to live-migrate after this offline snapshot is taken, the migration may still hang because target node cannot read source's in-memory LVM table. For a shared SAN layout using LVM Thick, you should use these offline snapshots as temporary capture points, back them up off-site using an operator like OADP, and then immediately delete the local snapshot to keep the VM clear for seamless live migrations.


== Deploy operator

.install.sh
[source,bash]
----
oc new-project piraeus-datastore
oc apply --server-side -f "https://github.com/piraeusdatastore/piraeus-operator/releases/latest/download/manifest.yaml"
----

=== Setup security

Openshift specific tweaks:

.policy.sh
[source,bash]
----
oc adm policy add-scc-to-user privileged -z linstor-satellite-sa -n piraeus-datastore
oc adm policy add-scc-to-user privileged -z linstor-csi-controller-sa -n piraeus-datastore
oc adm policy add-scc-to-user privileged -z linstor-csi-node-sa -n piraeus-datastore
----

.roles.sh
[source,bash]
----
oc apply -f - <<EOF
kind: ClusterRole
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: linstor-csi-node-pv-patch
rules:
  - verbs:
      - get
      - list
      - watch
    apiGroups:
      - ''
    resources:
      - persistentvolumes
---
kind: ClusterRoleBinding
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: linstor-csi-node-pv-patch-binding
subjects:
  - kind: ServiceAccount
    name: linstor-csi-node
    namespace: piraeus-datastore
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: linstor-csi-node-pv-patch
EOF
----

=== Setup Satellite


.satelite.sh
[source,bash]
----
oc apply -f - <<EOF
apiVersion: piraeus.io/v1
kind: LinstorSatelliteConfiguration
metadata:
  name: pure-san-storage-satellites
spec:
  podTemplate:
    spec:
      initContainers:
        - $patch: delete
          name: drbd-module-loader  
      volumes:
        - $patch: delete
          name: lib-modules
      automountServiceAccountToken: true

.cluster.sh
[source,bash]
----
oc apply -f - <<EOF
apiVersion: piraeus.io/v1
kind: LinstorCluster
metadata:
  name: linstorcluster
spec:
  csiController:
    enabled: true
    podTemplate:
      spec:
        automountServiceAccountToken: true
  csiNode:
    enabled: true
    podTemplate:
      spec:
        automountServiceAccountToken: true

=== Configure Storage Pool

.createPool1.sh 
[source,bash]
----
# 1. Clear out the non-shared mappings
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool delete bm208.pietersmalan.com pool1
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool delete bm209.pietersmalan.com pool1

# 2. Re-create the pools using an identical shared-space token (e.g., "san-backing-pool")
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool create lvm bm208.pietersmalan.com pool1 vg_piraeus/pool1 --shared-space san-backing-pool
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool create lvm bm209.pietersmalan.com  pool1 vg_piraeus/pool1 --shared-space san-backing-pool
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool list

# This forces the LINSTOR satellites to rebuild their capacity map for pool1
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool modify bm208.pietersmalan.com pool1 --property Autoplace/Force=true
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool modify bm209.pietersmalan.com pool1 --property Autoplace/Force=true
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor storage-pool list
----

=== Configure Resource Group

./resourcegroup.sh 
[source,bash]
----
# 1. Create the group
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor resource-group create piraeus-storage

# 2. Lock it to 1 replica (no DRBD mirrors since your SAN handles HA)
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor resource-group modify piraeus-storage --place-count 1

# 3. Enable automated diskless attachments for smooth VM live migrations
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor resource-group modify piraeus-storage --diskless-on-remaining true

# 4. Tie it directly to your raw SAN storage pools
oc exec -n piraeus-datastore deployment/linstor-controller -- linstor resource-group modify piraeus-storage --storage-pool pool1
----

=== Create Storage Class

.storageclass.sh
[source,bash]
----
oc appl -f - <<EOF
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: piraeus-storage
  annotations:
    storageclass.kubevirt.io/is-default-virt-class: 'true'
provisioner: linstor.csi.linbit.com
parameters:
  linstor.csi.linbit.com/allowRemoteVolumeAccess: 'true'
  linstor.csi.linbit.com/autoPlace: '1'
  linstor.csi.linbit.com/layerList: STORAGE
  linstor.csi.linbit.com/placementCount: '1'
  linstor.csi.linbit.com/storagePool: pool1
reclaimPolicy: Delete
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
----

.snapshotclass.sh
[source,bash]
----
oc apply -f - <<EOF
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: piraeus-rwx-snapshot-class
driver: linstor.csi.linbit.com
deletionPolicy: Delete
parameters:
  # Allows LINSTOR to ignore active attachments during a snapshot sequence
  allow-active-multi-node: "true"
EOF
----

== Node Preparation

We need to install dm-snapshot module:

NOTE: Adapt master/worker roles as required.

.modprobe.sh
[source,bash]
----
oc apply -f - <<EOF
apiVersion: machineconfiguration.openshift.io/v1
kind: MachineConfig
metadata:
  labels:
    machineconfiguration.openshift.io/role: master
  name: 99-master-dm-snapshot
spec:
  config:
    ignition:
      version: 3.2.0
    storage:
      files:
      - contents:
          source: data:,dm-snapshot%0A
        mode: 420
        overwrite: true
        path: /etc/modules-load.d/dm-snapshot.conf
EOF
----

NOTE: Only for verification, Linstor/Piraeus is a recognized CSI driver in OpenShift, so the StorageProfile should be correct:

.StorageProfile
[source,yaml]
----
apiVersion: cdi.kubevirt.io/v1beta1
kind: StorageProfile
metadata:
  name: piraeus-storage
spec:
  claimPropertySets:
    - accessModes:
        - ReadWriteMany
      volumeMode: Block
    - accessModes:
        - ReadWriteOnce
      volumeMode: Block
    - accessModes:
        - ReadWriteOnce
      volumeMode: Filesystem
    - accessModes:
        - ReadOnlyMany
      volumeMode: Block
    - accessModes:
        - ReadOnlyMany
      volumeMode: Filesystem
  cloneStrategy: snapshot
  dataImportCronSourceFormat: pvc
  snapshotClass: piraeus-rwx-snapshot-class
----
